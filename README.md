# Simple Design System - POC

This project aims to create a proof of concept to prove that the assumptions about the advantages and benefits obtained from a design system in the defined state [here](InitialTheoreticalDocument.md) are real. That is, starting from a design system in such a state of definition, AI can be used intensively to generate code.

## Initial Setup

The first step when setting up the project is to rename `.env-rename` to `.env`, including your `FIGMA_ACCESS_TOKEN`, which must be previously configured with the required scope permissions.

- `npm i` to install dependencies
- `npm run app:dev` will run server at [localhost:8000](http://localhost:8000) which renders contents of [App.tsx](src/App.tsx)
- `npm run storybook` to start storybook at [localhost:6006](http://localhost:6006)

### Figma Auth

- [Create a Figma API token](https://www.figma.com/developers/api#authentication)
  - Add Code Connect scope
  - Add File Read, Dev Resources Write, and Variables scopes if you want to use the integrations in [scripts](./scripts/)
  - [More on scopes](https://www.figma.com/developers/api#authentication-scopes)
- Duplicate [.env-rename](./.env-rename)
- Rename it to `.env`, it will be ignored from git.
  - Set `FIGMA_ACCESS_TOKEN=` as your token in `.env`
  - Set `FIGMA_FILE_KEY=` as your file's key (grab it from the file URL) in `.env`

### Code Connect

SDS is fully backed by Figma's Code Connect. This includes examples for how to connect [primitives](./src/figma/primitives/), as well as [compositions](./src/figma/compositions/) of those primitives for your design system.

This repo utilizes `documentUrlSubstitutions` in [figma.config.json](./figma.config.json). This allows us to keep our docs Figma file-agnostic and colocates all the Figma file-specific information for easy url swapping. The document URL substitutions are also named in a way that helps you find the associated component without clicking a link. A key `<FIGMA_INPUTS_CHECKBOX_GROUP>` is broken down as `<FIGMA_[PAGE_NAME]_[COMPONENT_NAME]>`.

```json
{
  "documentUrlSubstitutions": {
    "<FIGMA_INPUTS_CHECKBOX_GROUP>": "https://figma.com/design/whatever?node-id=123-456"
  }
}
```

Allows us to have more expressive URLs in our Code Connect docs:

```js
figma.connect(CheckboxGroup, "<FIGMA_INPUTS_CHECKBOX_GROUP>");
```

## Project Structure

The code is located in the `src` folder and is divided into two main parts:

### `ds` Folder

Contains all the code related to the design system. Within that directory, code is broken down into a few categories.

#### [src/ds/ui/compositions](./src/ds/ui/compositions/)

Example arrangements of primitive components to demonstrate how you might use SDS to build a responsive website.

#### [src/ds/ui/hooks](./src/ds/ui/hooks/)

Custom React hook definitions

#### [src/ds/ui/icons](./src/ds/ui/icons/)

All icon components. Automatically generated by [scripts/icons](./scripts/icons)

#### [src/ds/ui/images](./src/ds/ui/images/)

Placeholder images.

#### [src/ds/ui/layout](./src/ds/ui/layout/)

Layout components. Crucial to SDS layouts, but do not have analogous component in Figma.

#### [src/ds/ui/primitives](./src/ds/ui/primitives/)

The main component library. SDS primitives can't be reduced further into sub components.

#### [src/ds/ui/providers](./src/ds/ui/providers/)

Custom React provider definitions

#### [src/ds/ui/utils](./src/ds/ui/utils/)

Custom utilities and utility components

#### Code Connect and Storybook

All Code Connect docs and Storybook stories follow the same categorization are defined in [src/ds/figma](./src/ds/figma) and [src/ds/stories](./src/ds/stories).

**Recent Implementations:**

- New variant for `Button` component
- New variant for `AvatarGroup` component
- `Calendar` component
- New design tokens

### `app` Folder

Contains the test application component that was generated during the process, based on example pages already created by the Figma team, which can be found at: [Figma Example Pages](https://www.figma.com/community/file/1380235722331273046/simple-design-system).

## Technical Stack

### Backend Simulation

To simulate a realistic development context, a backend based on the `json-server` library was used.

### Data Model

A fully typed data model was created to also evaluate the AI's performance in inferring these types.

### Routing

`react-router` v5 was installed for application routing, with defined management and organizational rules, including protected routes.

### State Management

`tanstack-query` v5 was installed for server state management.

### Testing

`vitest` was installed to provide an appropriate testing environment.

## AI Integration

### Prompt History

A folder called `promptsHistory` exists in both `ds` and `app` to maintain a history of the most important prompts used.

### Architecture Documentation

In the `app` folder:

- `FEArchitecture.md` - Compiles cross-cutting information about the architecture that the project should follow, according to the current onDMARC convention
- `specs/AppSpec.md` - Provides the AI with a high-level context of this application

### Copilot Instructions

`.github/copilot-instructions.md` - Provides all the context regarding the design system

### AI Skills

Other AI consumables are included as skills in `.agents`. Some are generic skills for specific technologies, installed from Vercel's public skills registry:

- `tanstack-query`
- `vercel-composition-patterns`
- `typescript-advanced-types`
- `code-connect-components`
- `create-design-system-rules`
- `implement-design`
- `react-useeffect`

### Custom Skills

Other skills were created custom to provide the AI with specific knowledge:

- **`router-navigation-management`** – Provides the AI with all necessary information on how to manage routes using react-router v5
- **`json-server-mock-api`** – Information extracted from the json-server documentation to provide the AI with the knowledge required to use the library
- **`sds-XXXXX`** – Specifications required for implementing components of the design system. These include constraints and rules applied to the design system, mostly related to layout
